## Decisions and risks to track

- The default command is diagnostic-only, with exit 0 for warnings and exit 1 for errors. Automation that
  requires a fully clean/complete result must inspect the JSON fields.
- Read-only guarantees require separate registry access and explicit control over scanner runtime clients;
  simply composing existing CLI commands does not satisfy the contract.
- Host rules guide behavior but do not guarantee that all sessions retain a stable identity. The real-host
  acceptance record and fallback wording are part of the deliverable.
- Service diagnosis must degrade when observation is incomplete; reusing a snapshot does not remove the
  need to track scan coverage and liveness uncertainty.
