# PortMarshal v0.8.1 — Attribution Fixes

## Goal

Prevent an old, unlistened cooperative claim from changing the identity or warning state of an otherwise
healthy live service in the same project. Keep the stale record visible for explicit review without changing
the v0.8 service snapshot schema or destructive-action safeguards.

## Root cause

The v0.8 aggregator attached any unassigned claim to the sole active service in the same canonical project.
That weak project-only fallback was useful for fresh port drift, but it also attached claims that already met
the `gc` stale threshold. For a Vite project, an old preview claim on 4173 could therefore rename and mark a
normal development listener on 5173 as drift.

Separately, SwiftBar 2.1.1 can gray submenu content after incremental updates. PortMarshal does not emit a
disabled attribute for these rows; this upstream rendering issue is outside the service-attribution model.

## Policy

- A claim is stale only when it is active, its port is not listening, and its age is greater than 30 minutes.
- Service snapshots and `gc` use the same helper and strict boundary; exactly 30 minutes is not stale.
- A stale claim is always represented as a separate claim-only service with a `stale-claim` warning.
- A stale claim never renames a live service, contributes a drift claim to it, or changes its stable identity.
- Fresh unmatched claims retain the v0.8 related/drift behavior for compatibility.
- A dead managed run retains the stronger `managed-run-dead` warning.
- Claim-only SwiftBar rows use the claim name; active rows continue to use the canonical project basename.

## Compatibility

`ServiceSnapshot.schemaVersion` remains `1`. No enum or CLI flag changes are required; `stale-claim` is an
additive warning string. Per-port output, stop authorization, claim ownership, and `gc` mutation semantics
remain unchanged.

## Acceptance case

Given one active Cursor/Vite listener for `/p/alab_frontend` on 5173 and an active claim named
`alab-preview-review` on unlistened port 4173 that is older than 30 minutes:

- the 5173 service is named `alab_frontend`, has no attached claim, and has no warning;
- the 4173 claim is a separate reserved service named `alab-preview-review` with `stale-claim`;
- SwiftBar renders one normal 5173 row and one orange 4173 review row;
- `gc --dry-run` reports the same 4173 claim as stale without changing registry state.

## Release gates

- targeted regression tests for service attribution, menu rendering, and the exact stale boundary;
- full build, unit test suite, and real-listener smoke test;
- package dry run and public tarball/provenance verification;
- main CI must pass before tagging; npm OIDC publish must pass before creating the GitHub Release.
